# aidkq — AI 기반 TC 자동 생성 도구 (Lv.1 프롬프트 세트)

기획서·피그마를 분석해 검증 대상을 도출하고, 회사 양식에 맞는 TC 초안을 만들고, 품질을 스스로 점검하는 QA 보조 도구.
이 저장소는 로드맵 **Lv.1**이다. 코드 없이 프롬프트와 지식 파일만으로 효과를 먼저 검증한다.

## 구성

```
knowledge/                  Claude 프로젝트 "지식"에 등록할 파일
  tc-writing-rules.md       TC 문장 규칙, 분리·병합 기준, 금지어 (기획서 8.3~8.4)
  exception-checklist.md    전 화면 공통 예외 체크리스트 (8.2)
  validation-rules.md       R01~R10 룰 + AI 점검 항목 (9장)
  rulebook.sample.md        공통 규칙집 초안 양식 (7.2) — 담당 서비스 규칙으로 교체
  format-profile.sample.json 양식 프로파일 예시 (7.1) — 01 프롬프트 결과로 교체

prompts/                    단계별 프롬프트 (순서대로 사용)
  01-format-profile.md      STEP 0  기존 TC → 양식 프로파일
  02-requirements.md        STEP 1  기획서 → 요구사항 구조화 + 질의 목록
  03a-test-conditions.md    STEP 3  요구사항 → 테스트 조건 목록 (사람 승인)
  03b-test-cases.md         STEP 4+5 승인된 조건 → TC 초안 + 자가 검증 리포트

schemas/                    각 단계 출력 JSON 스키마
samples/                    검증용 가상 기획서와 정답지 TC
evaluation/                 정답지 대비 품질 비교 리포트 양식
```

기획서의 "프롬프트 3종"에서 ③(조건 도출 → TC 생성)은 03a / 03b 두 파일로 나눴다.
원칙 3("한 번에 끝내지 않는다")에 따라 조건 목록을 사람이 승인한 뒤에만 TC 문장을 만든다.
STEP 2(앱 지식 베이스 대조)는 Lv.4 범위라 Lv.1에서는 생략하고, 기존 화면 정보는 규칙집에 수동으로 적어 대체한다.

## 사용 방법

### 1. Claude 프로젝트 준비 (최초 1회)
1. Claude에서 새 프로젝트를 만든다.
2. `knowledge/` 아래 파일을 전부 프로젝트 지식에 업로드한다.
3. 회사 기존 TC 20~30건을 준비한다(사내 자료면 보안 승인 먼저, 14.1 참고).
4. `prompts/01-format-profile.md`를 실행해 양식 프로파일을 만든다. 결과 JSON을 확인·수정한 뒤
   `format-profile.json`으로 저장하고 프로젝트 지식의 sample 파일과 교체한다.

### 2. 기능 하나당 흐름
| 순서 | 프롬프트 | 넣을 것 | 사람이 할 일 |
|---|---|---|---|
| 1 | 02-requirements | 기획서 원문 (+ 피그마 텍스트가 있으면 함께) | 질의 목록 답변, 답변을 붙여 재실행하거나 그대로 진행 |
| 2 | 03a-test-conditions | 02의 JSON 출력 | 조건별 채택/삭제/추가 표시 |
| 3 | 03b-test-cases | 승인된 조건 목록 | TC 문구 수정, 검증 리포트의 오류 해결 |

각 단계는 새 대화에서 실행해도 되고 한 대화에서 이어가도 된다. 이어갈 때는 이전 단계 출력을 그대로 붙여넣는다.

### 3. 품질 비교 (Lv.1 산출물)
1. `samples/sample-spec.md`(가상 기획서)로 전 과정을 수행한다.
2. 생성 결과를 `samples/golden-tc.csv`(사람이 직접 쓴 정답지)와 비교한다.
3. `evaluation/comparison-report.md` 양식에 수치를 채운다.
4. 결과로 Lv.2(구글 시트 연동) 착수 여부를 판단한다.

실제 담당 서비스로 비교할 때는 정답지를 본인이 이미 작성한 TC 세트로 바꾼다.

## 수정 이력 남기기
원칙 5("쓸수록 정확해진다")를 Lv.1에서도 흉내낸다. 03b 결과를 고칠 때마다
`evaluation/edit-log.md`에 before/after를 한 줄씩 적는다. 같은 유형의 수정이 3회 반복되면
`knowledge/rulebook.sample.md`에 규칙으로 올리고 프로젝트 지식을 갱신한다.

## 보안
- 고객사 기획서·피그마는 사전 승인 전 외부 AI에 넣지 않는다.
- 승인 전에는 공개 서비스 기반 가상 기획서(`samples/`)나 개인 프로젝트로만 검증한다.
- 포트폴리오로 공개할 때는 가상 데이터로 재구성한다.
