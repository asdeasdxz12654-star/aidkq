# TC 작성 규칙

모든 TC 생성·검토 단계에서 이 문서를 따른다. 양식 프로파일(format-profile.json)의 문체 규칙과 충돌하면 **양식 프로파일이 우선**한다. 단, 근거·금지어 규칙은 항상 적용한다.

## 1. 근거 원칙
- 모든 기대결과는 다음 중 하나를 근거로 가진다: 기획서 문장, 피그마 요소, 규칙집 항목.
- 근거를 댈 수 없는 내용은 TC로 쓰지 않고 **질의 항목**으로 돌린다.
- 근거가 규칙집(암묵 규칙)이면 출처에 `규칙집: <분류>-<항목>`으로 표기한다.
- 추측으로 문구를 만들지 않는다. 기획서에 문구 원문이 없으면 `[문구 미정의 — Q번호]`로 남긴다.

## 2. 필드별 문장 규칙
| 필드 | 규칙 | 좋은 예 | 나쁜 예 |
|---|---|---|---|
| 테스트 항목 | `[조건] 시 [대상]의 [무엇] 확인`. 판정 기준을 쓰지 않는다 | 온보딩 화면 5초 경과 시 자동 전환 확인 | 5초 후 신규 3D방으로 정상 이동하는지 확인 |
| 사전조건 | 계정 상태, 진입 이력, 시작 화면을 명시 | 로그인 상태 / 3D방 최초 진입 / 전체 메뉴 화면 | 앱 실행 |
| 절차 | 행동만 번호로 작성. 결과 서술 금지 | 1. "3D 방꾸미기 시작하기" 버튼 선택 | 1. 버튼 선택 후 화면 이동됨 |
| 기대결과 | 절차 번호에 대응. `~된다 / ~노출된다`로 종결. 문구는 원문 그대로 큰따옴표로 | 1. 신규 3D방 편집 화면으로 이동된다 | 1. 정상적으로 이동되는지 확인 |
| 우선순위 | 데이터 저장·결제·이동 불가 = 상 / 기능 동작 = 중 / 문구·레이아웃 = 하 (양식 프로파일 등급명 사용) | | |
| 출처 | 기획서 버전+페이지, 피그마 프레임명 중 최소 1개 필수 | 기획서 v1.0 p.3 / 피그마 "온보딩" | (빈칸) |

## 3. 금지어 (기대결과·테스트 항목)
`정상`, `정상적`, `올바르게`, `올바른`, `잘`, `적절히`, `적절한`, `문제없이`, `원활히`, `제대로`
→ 대신 "무엇이 / 어디에 / 어떤 문구로 / 몇 초 후" 를 쓴다.

## 4. 분리·병합 기준
조건 1개 = TC 1개가 기본이다. 아래 기준으로 조정한다.

**분리한다**
- 기획 근거 문서(또는 페이지 섹션)가 다를 때
- 확인하는 화면이 다를 때 (현재 화면 반응 vs 이동 후 데이터 반영)
- 우선순위가 다를 때 (데이터 저장 = 상, 문구 = 하)
- 사전조건이 다를 때 (로그인 / 비로그인, 최초 / 재진입)

**병합한다**
- 하나의 상태를 구성하는 요소일 때 (에러 시 테두리 색 + 에러 문구)
- 같은 화면에서 동시에 확인 가능한 UI 구성 요소일 때

**과다 병합 신호**: 기대결과가 5개를 넘으면 분리를 검토한다.

## 5. Given-When-Then 자가 점검
생성한 TC를 "~인 상태에서(Given) / ~하면(When) / ~된다(Then)"로 재구성한다.
When이 둘 이상이면 분리 대상으로 표시한다. 단, 한 흐름의 연속 행동(입력 → 선택)이 하나의 판정을 위한 것이면 예외로 둔다.

## 6. 경계값 표기
- 길이·수량·시간 제한은 `최소-1 / 최소 / 최대 / 최대+1` 4점을 기본으로 한다.
- 시간 경계는 기획 수치 기준 직전·직후를 쓴다 (예: 5초 타이머 → 4초 시점 선택, 5초 경과 대기).
- 입력값은 실제 값을 적는다 ("7자 입력" 대신 `abcd123` (7자)).
