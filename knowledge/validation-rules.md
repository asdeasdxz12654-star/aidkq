# 품질 검증 규칙

TC 초안 생성 직후 전 건을 점검한다. 결과는 검증 리포트로 출력한다. **오류**가 남은 TC는 내보내기 전에 반드시 수정한다.

## 1. 룰 기반 검증
| 코드 | 검사 내용 | 수준 |
|---|---|---|
| R01 | 기대결과에 금지어(정상, 올바르게, 잘, 적절히, 문제없이, 제대로 등) 포함 | 오류 |
| R02 | 기대결과가 "확인"으로 종결 (테스트 항목 문장 혼입) | 오류 |
| R03 | 테스트 항목과 기대결과가 사실상 같은 문장 (판정 기준 없이 항목을 반복) | 오류 |
| R04 | 요구사항 출처 누락 | 오류 |
| R05 | 사전조건 누락 | 경고 |
| R06 | 절차에 결과 서술 포함 ("~노출", "~된다", "~이동됨") | 경고 |
| R07 | 기대결과 항목 5개 초과 (과다 병합 의심) | 경고 |
| R08 | TC ID 중복 또는 양식 프로파일 ID 패턴 불일치 | 오류 |
| R09 | 사전조건·절차가 동일한 중복 TC | 경고 |
| R10 | 기대결과 문구가 기획서/피그마 원문과 불일치 | 경고 |

"금지어" 판정 시 고유명사·원문 인용(큰따옴표 안) 속 단어는 제외한다. 예: `"정상 처리되었습니다" 토스트가 노출된다`는 R01 위반이 아니다.

## 2. AI 기반 점검
| 코드 | 검사 | 방법 |
|---|---|---|
| A01 | 환각 검출 | 기대결과마다 근거 문장을 인용한다. 인용할 수 없으면 표시 |
| A02 | 커버리지 | 요구사항의 기능·요소·조건 목록 대비 TC가 없는 항목 표시 |
| A03 | 예외 누락 | 예외 체크리스트(EX01~EX11) 중 판정되지 않은 항목 표시 |
| A04 | 재현 가능성 | 절차만 보고 제3자가 수행 가능한지 평가 (입력값·시작 화면 누락 등) |
| A05 | GWT 분리 | When이 둘 이상인 TC 표시 |

## 3. 검증 리포트 형식
```
## 검증 리포트
- 총 TC: n건 / 오류: n건 / 경고: n건
- 내보내기 가능 여부: 가능 | 불가(오류 n건)

### 위반 목록
| TC ID | 코드 | 수준 | 내용 | 수정 제안 |

### 미커버 항목 (A02)
- REQ-xx 요소/조건명 — 사유

### 예외 미판정 (A03)
- 화면명 EXxx

### 질의 필요 항목
- Q-xx 질의 문장 (관련 TC ID)
```
