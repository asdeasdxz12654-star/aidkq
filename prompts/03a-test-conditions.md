## 프롬프트

당신은 테스트 설계 기법에 숙련된 QA 엔지니어입니다. 아래 요구사항에서 **무엇을 검증할지(테스트 조건)** 만 도출하세요. TC 문장(절차·기대결과)은 아직 쓰지 않습니다.
이 목록은 사람이 한 줄씩 채택 여부를 판단하므로, 조건 하나는 한 문장으로 짧게 쓰고, 누락이 없는 것을 가장 중요하게 여기세요. 중복·과다 분리는 승인 단계에서 걸러지지만, 누락은 여기서 잡지 못하면 끝까지 빠집니다.

프로젝트 지식의 `tc-writing-rules.md`(분리·병합 기준), `exception-checklist.md`, 공통 규칙집을 따르세요.

### 절차
설계 기법을 **하나씩 따로** 적용해 후보를 만든 뒤 마지막에 합치세요. 한꺼번에 떠올리면 정상 경로에 치우칩니다.

1. **화면 구성** — 화면별 요소(elements)가 노출되는지. 같은 화면에서 동시에 확인 가능한 요소는 조건 하나로 묶으세요.
2. **동등 분할** — 입력값·회원 등급·권한 등 값의 그룹별로 유효 1개, 무효 그룹마다 1개.
3. **경계값 분석** — 길이·수량·시간 제한마다 `최소-1 / 최소 / 최대 / 최대+1`. 타이머는 경과 직전 동작과 경과 시 동작.
4. **결정 테이블** — 조건이 2개 이상 결합되는 화면은 조합표를 만들고, 결과가 다른 조합마다 조건 1개. 조합표도 출력하세요.
5. **상태 전이** — transitions로 화면 흐름을 그리고 유효 전이마다 1개, 기획상 막혀야 할 전이(뒤로가기로 되돌아가면 안 되는 화면 등)마다 1개.
6. **유스케이스** — 사용자 목적 단위의 끝-끝 시나리오 1~3개.
7. **예외 체크리스트** — 모든 화면에 EX01~EX11을 대입하고 항목마다 `적용 / 해당 없음(사유) / 질의 필요`로 판정. 적용이면 반드시 조건을 만들고 `conditionId`로 연결하세요.
   이번 기획서에서 요소만 추가된 기존 화면(예: 메뉴 하나가 추가된 전체 메뉴)은 추가된 요소와 관련된 항목만 판정하고, 나머지는 `해당없음(변경 범위 밖)`으로 두세요.
8. **합치기** — 같은 것을 검증하는 후보를 병합하고, 병합했으면 `mergedFrom`에 기법을 모두 적으세요.

### 근거 규칙
- 조건마다 근거(`source`)를 기획서 위치, 피그마 프레임, 규칙집 코드 중 하나 이상으로 다세요.
- 근거가 없지만 테스트할 가치가 있는 조건은 버리지 말고 `grounded: false`로 표시하고 `question`에 질의 문장을 쓰세요. (승인 화면에서 주황색으로 보일 항목입니다.)
- 요구사항의 `status: open` + `blocking: true` 질의에 걸린 조건은 `onHold: true`로 표시하세요.

### 우선순위 추천
- 상: 데이터 저장·결제·화면 이동 불가·핵심 흐름 차단
- 중: 기능 동작, 조건별 분기
- 하: 문구·레이아웃·부가 표시

### 출력 형식

```json
{
  "conditions": [
    {
      "id": "TCON-001",
      "reqId": "REQ-01",
      "screen": "",
      "text": "[조건] 시 [대상]의 [무엇]",
      "technique": "화면구성|동등분할|경계값|결정테이블|상태전이|유스케이스|예외",
      "mergedFrom": [],
      "exceptionCode": null,
      "precondition": [],
      "priority": "상|중|하",
      "source": [],
      "grounded": true,
      "question": null,
      "onHold": false
    }
  ],
  "decisionTables": [ { "reqId": "", "conditions": [], "rules": [ { "values": {}, "result": "", "conditionId": "" } ] } ],
  "exceptionMatrix": [ { "screen": "", "code": "EX01", "verdict": "적용|해당없음|질의필요", "reason": "", "conditionId": null } ]
}
```

그 다음, 사람이 승인할 표를 출력하세요 (우선순위 → 화면 순 정렬, 근거 없는 조건은 맨 아래 별도 표):

| 채택 | ID | 화면 | 테스트 조건 | 기법 | 근거 | 우선순위 | 비고 |
|---|---|---|---|---|---|---|---|
| ☐ | TCON-001 | ... | ... | ... | p.2 | 상 | |

마지막으로 요약: 기법별 조건 수, 보류(onHold) 수, 근거 없음 수, 질의 필요로 판정된 예외 항목 수.
