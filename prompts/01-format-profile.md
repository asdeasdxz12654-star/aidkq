# 01. 양식 프로파일 추출 (STEP 0, 최초 1회)

- 입력: 회사 기존 TC 20~30건 (엑셀을 복사해 붙여넣거나 CSV 첨부)
- 출력: 양식 프로파일 JSON (`schemas/format-profile.schema.json`) + 확인 필요 사항
- 사람이 할 일: 컬럼 역할 매핑과 분리 단위(granularity)를 확인하고 `confirmedByUser`를 true로 바꾼다

---

## 프롬프트 (아래를 그대로 복사)

당신은 QA 팀의 TC 양식을 분석하는 역할입니다. 아래 기존 TC 샘플에서 이 회사의 TC 양식 규칙을 추출해 양식 프로파일을 만드세요.
목적은 이후 AI가 생성하는 TC가 이 회사 사람이 쓴 것과 같은 형식·문체·상세도를 갖게 하는 것입니다. 표준 양식을 제안하지 말고, 샘플에 실제로 나타난 규칙만 기술하세요.

<tc_samples>
{여기에 기존 TC를 붙여넣기 — 헤더 행 포함}
</tc_samples>

다음 순서로 분석하세요.

1. **컬럼 매핑**: 각 컬럼에 역할을 하나 붙이세요. 역할: `id, category1, category2, category3, item, precondition, steps, expected, priority, source, result, note, other`.
   결과 컬럼이 플랫폼별로 나뉘면 `perPlatform`을 적으세요. 역할을 확신할 수 없으면 `other`로 두고 확인 필요 사항에 적으세요.
2. **ID 규칙**: ID 패턴을 `{화면약어}-{3자리}` 같은 템플릿으로 추정하고, 샘플에 나온 화면명→약어 대응을 `idAbbreviations`에 적으세요.
3. **문체**: 컬럼별 종결 어미(명사형 "~ 확인", "~된다", "~노출됨" 등), 번호 매김 방식, 줄바꿈 방식, 문구 인용 부호를 적으세요.
   가장 많이 쓰인 형태를 규칙으로 삼고, 소수 예외는 무시하되 개수를 확인 필요 사항에 남기세요.
4. **용어**: 같은 동작을 가리키는 용어가 통일돼 있으면 `terminology`에 적으세요 (예: 탭/클릭 → "선택").
5. **우선순위·결과 값**: 실제로 쓰인 값 목록을 그대로 적으세요.
6. **분리 단위**: TC당 기대결과 항목 수의 평균·최대를 계산하고, "한 화면 = 1 TC" / "요소 하나 = 1 TC" / "시나리오 = 1 TC" 중 무엇에 가까운지 판단하세요. 계산 근거(샘플 수, 합계)를 확인 필요 사항에 적으세요.
7. **우수 예시**: 이후 생성의 본보기로 쓸 TC 5건을 고르세요. 기준: 기대결과가 판정 가능하고(모호 표현 없음), 절차에 결과 서술이 없고, 서로 다른 유형(화면 구성 / 동작 / 입력 검증 / 예외)을 대표하는 것. 원문을 그대로 옮기세요.

출력 형식:

```json
{ ...schemas/format-profile.schema.json 형식의 양식 프로파일... }
```
