# Lv.1 품질 비교 리포트

- 실행일: 2026-09-18 ~ 2026-09-19
- 모델: Claude Opus 5 (Claude Code 세션)
- 대상 기획서: samples/sample-spec.md (v1.0)
- 정답지: samples/golden-tc.csv (23건), samples/expected-questions.md (질의 11건 + 추가 발견 5건)
- 실행자: 저장소 작성자 본인
- 원본 데이터: `runs/2026-09-18-dryrun/`

> **이 수치는 공식 지표가 아니다.**
> 수행자가 정답지(`golden-tc.csv`, `expected-questions.md`)를 직접 작성한 당사자다. blind 테스트가 아니므로
> 탐지율·커버리지는 상한에 가깝게 나온다. 이 리포트의 용도는 **프롬프트·스키마·검증 규칙의 결함 찾기**이고,
> Lv.2 착수 판단에 쓸 수치는 정답지를 보지 않은 실행자가 같은 절차를 돌려 다시 측정해야 한다.

## 5. 검증 리포트 신뢰도
| 항목 | 수치 |
|---|---|
| 03b가 보고한 오류 / 경고 | 최초 3 / 5 → 조치 후 **0 / 4** |
| 사람이 확인한 실제 위반 중 리포트가 놓친 것 | 미측정 (사람 검토 전) |
| 리포트가 잘못 지적한 것 (오탐) | 0건 |

- 최초 오류 3건은 모두 같은 원인이었다. 양식 프로파일에 "전체 흐름" 화면 약어가 없어 FLOW-001~003의 ID가 패턴에 맞지 않았다. 프로파일에 `"전체 흐름": "FLOW"`를 추가해 해소했다.
- 경고 1건(FLOW-001의 기대결과 5개)은 프로파일 `granularity.exceptions`에 유스케이스 예외(최대 8)를 두어 해소했다.
- 남은 경고 4건은 전부 A01 유추 근거다. Q-17·Q-18·Q-19 답변 전까지 Fail 판정 근거로 쓰지 않는다.
- **리포트 자체의 결함도 하나 나왔다**: 이 실행 내내 정답지를 22건으로 세고 있었다. 실제는 23건이다(2026-09-19 정정). 수치를 손으로 옮겨 적는 구간은 기계 대조로 바꿔야 한다.

## 6. 결론
- **Lv.2 착수 여부: 보류 — blind 재측정 후 판단**
- 근거:
  - 커버리지 100%, 무효 TC 0건, 추가 커버리지 17건은 좋은 신호다. 그러나 수행자가 정답지 작성자와 동일해 수치를 그대로 쓸 수 없다.
  - 반대로 **결함 찾기 용도로는 충분히 작동했다.** 4단계를 돌리는 동안 프롬프트·스키마·도구에서 고칠 것이 6건 나왔고 전부 반영했다.
  - 초안 채택률(목표 60%)은 사람이 문구를 고치는 단계를 거쳐야 나온다. 이 수치 없이는 Lv.2 투자 판단이 어렵다.
- 다음 측정 설계:
  1. 정답지를 보지 않은 실행자가 `samples/sample-spec.md`로 02 → 03a → 03b를 수행한다
  2. 단계별 시작·종료 시각을 기록한다
  3. 03b 결과를 사람이 검토·수정하고 `evaluation/edit-log.md`에 남긴다 → 초안 채택률 산출
  4. 정답지 대응은 실행자가 아닌 제3자가 판정한다
